The following implementation risks need resolution within that reconciled spec:

- **Direct HTTP MCP and asynchronous approvals need an explicit adapter contract.** The approved absence of a network relay does not eliminate the need for application code to retain an HA call while returning an eight-second provisional result. [Brief:258](/Users/jwang14/Projects/weixue/docs/briefs/feat-agent-service.md:258) supplies this through an in-process adapter, whereas DESIGN says HTTP MCP. Specify the boundary clearly. Exceeding eight seconds proves only that the result is pending; it does not prove HA is holding the call for approval.

- **Polling must not manufacture ownership.** [Brief:261](/Users/jwang14/Projects/weixue/docs/briefs/feat-agent-service.md:261) deduplicates globally by tool and arguments; [brief:265](/Users/jwang14/Projects/weixue/docs/briefs/feat-agent-service.md:265) correlates using truncated arguments and a time window. Another HA client can issue the same call, and different long arguments can share the same displayed prefix. A single matching candidate is not proof that the request belongs to this device. Preserve exact invocation identity where supported; ambiguous matches must remain non-actionable from the device.

- **Approval, execution, and replay require separate durable states.** Disappearance from `/pending` is not an execution receipt. The replay transition at [brief:273](/Users/jwang14/Projects/weixue/docs/briefs/feat-agent-service.md:273) needs positive decision evidence, a known final disposition of the original request, and a persisted replay-dispatch record. Test approval racing timeout, another client consuming approval, restart, and lost HTTP responses. Current upstream also distinguishes static calls from dynamic selectors, whose approvals cannot safely be reused across changed topology; verify the installed version before relying on generic identical-argument replay. [ha-mcp middleware](https://raw.githubusercontent.com/homeassistant-ai/ha-mcp/master/src/ha_mcp/policy/middleware.py).

- **All tools with one policy gate is viable only if that gate cannot be bypassed or modified by the agent.** Honor decision 19 without adding an unapproved application filter. Before enabling the full surface, verify the effective HA policy, proxy/meta-tool dispatch, policy-editing tools, and developer approval-management settings. Upstream conditionally exposes a policy-writing tool and documents separate developer approval-management functionality. This is a required verification, not a claim those capabilities are enabled on this installation. [Security-policy tool source](https://raw.githubusercontent.com/homeassistant-ai/ha-mcp/master/src/ha_mcp/tools/tools_security_policy.py).

- **SDK sessions are conversation persistence, not task recovery.** The actor model is sensible, but [brief:239](/Users/jwang14/Projects/weixue/docs/briefs/feat-agent-service.md:239) must not silently replace a failed resume with a fresh conversation under the same chat identity. Preserve the error and history association. Also reconcile safe post-result forks at [brief:58](/Users/jwang14/Projects/weixue/docs/briefs/feat-agent-service.md:58) with mid-turn side forks at [brief:250](/Users/jwang14/Projects/weixue/docs/briefs/feat-agent-service.md:250). Verify unfinished tool records, returned session IDs, and recovery before enabling side turns. [SDK session documentation](https://code.claude.com/docs/en/agent-sdk/sessions).

- **Interrupt must drain the old turn before admitting its successor.** A continuous receive pump helps, but FIFO attribution alone is insufficient unless interrupted results and buffered partial messages remain attached to their original generation. The SDK explicitly retains buffered messages after `interrupt()`. Verify abort acknowledgement, draining, subsequent queries, and already-dispatched HA work. [Python SDK reference](https://code.claude.com/docs/en/agent-sdk/python).

- **`can_use_tool` is not a universal filesystem guard.** The memory-only guard at [brief:230](/Users/jwang14/Projects/weixue/docs/briefs/feat-agent-service.md:230) may not see operations resolved earlier by permission rules or automatic read permissions. Enforce required non-HA boundaries through appropriate hooks and filesystem isolation, and test path traversal/symlinks. [SDK permission evaluation](https://code.claude.com/docs/en/agent-sdk/permissions).

However, auto-memory and global config are separate from setting-source selection. Test concurrent writers, restart integrity, unintended cross-chat instructions, and whether remembered content can influence approval handling. [SDK configuration and memory behavior](https://code.claude.com/docs/en/agent-sdk/claude-code-features).
